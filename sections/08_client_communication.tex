\subsection{Key Client Decisions}

\begin{itemize}
  \item \textbf{Build on the existing system} (C02, C03): the client gave the code and deployment manuals of the previous Laravel and React project.
        The team kept that stack (Table~\ref{tab:tech-decisions}).
  \item \textbf{One backend for web and mobile} (C06, C07): Leodega and Leodeguita share accounts, the warehouse model and the business rules.
        This is why Leodeguita is a client of the same REST API (Figure~\ref{fig:components}).
  \item \textbf{Organizations} (C06): a client can work under a company with several members.
        This became the Sprint~2 goal.
  \item \textbf{External inventory} (C01): clients connect their own inventory systems through an endpoint and a field mapping.
        This is planned for Sprint~4.
  \item \textbf{Simulated payment} (C11): the MVP uses a simulated payment instead of the Paganini gateway, which another team is still building.
        Real payment is postponed to a later phase.
  \item \textbf{Scope changes} (C11): any change to the signed scope must be discussed and accepted by both parties.
\end{itemize}
