\subsection{Key Client Decisions}

\begin{itemize}
  \item \textbf{Build on the existing system}: the client gave the code and deployment manuals of the previous Laravel and React project.
        The team kept that stack (Table~\ref{tab:tech-decisions}).
  \item \textbf{One backend for web and mobile}: Leodega and Leodeguita share accounts, the warehouse model and the business rules.
        This is why Leodeguita is a client of the same REST API (Figure~\ref{fig:components}).
  \item \textbf{Organizations}: a client can work under a company with several members.
        This became the Sprint~2 goal.
  \item \textbf{External inventory}: clients connect their own inventory systems through an endpoint and a field mapping.
        This is planned for Sprint~4.
  \item \textbf{Simulated payment} (C03): the MVP uses a simulated payment instead of the Paganini gateway, which another team is still building.
        Real payment is postponed to a later phase.
  \item \textbf{Scope changes} (C03): any change to the signed scope must be discussed and accepted by both parties.
\end{itemize}

\subsection{Acceptance Forms}

The Product Owner signed one acceptance letter per sprint on 2026-11-16 (C05 and C06).
Each letter lists the user stories of the sprint with their status.
All stories were accepted: 16 in Sprint~1 and 8 in Sprint~2, with none deferred or rejected.
These are the same stories listed in Section~\ref{sec:sprints}.
